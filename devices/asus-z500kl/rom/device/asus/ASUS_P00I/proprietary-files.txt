# The decryption path. qseecomd talks to the TrustZone and loads the keymaster
# trustlet from /firmware/image; keystore.msm8952.so is the real keymaster backend, and
# loading the software one instead is what made the TrustZone reject a correct PIN with
# -71 while bringing up the recovery.
#
# libdiag and libtime_genoff were missed in the first cut, and the first boot that got
# as far as system_server showed what that costs: libdrmfs links libdiag, qseecomd links
# libdrmfs, so qseecomd could not even start ("CANNOT LINK EXECUTABLE ... libdiag.so not
# found"); without it the keymaster never answers, keystore never registers, and
# system_server dies on a null IKeystoreService. Found with tools/missing-libs.sh run on
# the build output, which lists every DT_NEEDED that resolves nowhere.
#
# lib-imsSDP is IMS (VoLTE) and is left dangling on purpose: its dependencies
# (lib-imsdpl, lib-rtpcommon, and through them the QMI stack) belong to the RIL block.
# libsecureui's two missing libraries are added; lib-sec-disp exists only as 64-bit in
# the stock system, so the 32-bit libsecureui stays unusable, as it was on stock.

# Firmware the kernel loads at runtime: the Adreno microcode, Venus for the video
# codecs, and the display calibration data ASUS ships for the iris2 bridge.
#
# Only two Adreno files, and the kernel says which: adreno-gpulist.h gives the
# ADRENO_REV_A510 entry pm4fw_name "a530_pm4.fw" and pfpfw_name "a530_pfp.fw" -- the 510
# in this SoC runs the 530's microcode -- and unlike the A530 entries it declares no
# gpmufw_name and no zap_name, so those are not ours to carry.
#
# venus-v1 and not venus: the kernel log says which, in as many words --
# "subsys-restart: __subsystem_get(): Changing subsys fw_name to venus-v1" -- so the
# seven plain venus.* files are not this tablet's.
#
# iris2.fw is the Pixelworks bridge's own firmware, and it is easy to miss: nothing in
# the file names suggests it belongs to the display. The kernel asks for it by name at
# boot ("iris_firmware_download: request firmware: name = iris2.fw"), and without it the
# bridge never comes up.
#
# mTX1666T2_cfg.raw is the Atmel touch controller's configuration. About 15 s after
# boot the atmel_z500 driver re-checks the chip's config against it, and when the file
# is missing it soft-resets the controller five times looking for it (the TWRP tree
# ships the same file for the same reason). Missed in the first cut; the first M3 boots
# logged "could not find firmware for mTX1666T2_cfg.raw" over and over.
etc/firmware/mTX1666T2_cfg.raw

etc/firmware/a530_pfp.fw

etc/firmware/iris2.fw
